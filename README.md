# Orders Service

[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)
[![Python](https://img.shields.io/badge/Language-Python-blue.svg)](https://python.org/)

A RESTful microservice for the eCommerce back end built by the Orders squad of NYU CSCI-GA.2820 DevOps and Agile Methodologies (Fall 2026). An **Order** is a collection of **order items** created from products and quantities.

The service is written in Python with Flask, stores its data in PostgreSQL through SQLAlchemy, and returns JSON for every response, including errors.

## Data Model

### Order

| Field | Type | Notes |
|-------|------|-------|
| `order_id` | integer | Generated by the service |
| `customer_id` | integer | The customer that placed the order |
| `order_date` | datetime (ISO 8601) | Set when the order is created |
| `status` | string | Defaults to `pending` |
| `total_amount` | decimal string | Calculated by the service as the sum of `price * quantity` of all items |
| `items` | list of order items | Nested in every order response |

### Order Item

| Field | Type | Notes |
|-------|------|-------|
| `id` | integer | Generated by the service |
| `order_id` | integer | The order the item belongs to |
| `product_id` | integer | Must be a positive integer |
| `quantity` | integer | Must be a positive integer |
| `price` | decimal string | Unit price, must be zero or greater |

Deleting an order also deletes its items.

## API Endpoints

| Method | URL | Description | Success |
|--------|-----|-------------|---------|
| `GET` | `/` | Service name, version and the list URL | `200 OK` |
| `POST` | `/orders` | Create an order with its items | `201 Created` |
| `GET` | `/orders` | List all orders (optional `?customer_id=`) | `200 OK` |
| `GET` | `/orders/{order_id}` | Read an order | `200 OK` |
| `PUT` | `/orders/{order_id}` | Update an order's `customer_id` | `200 OK` |
| `DELETE` | `/orders/{order_id}` | Delete an order and its items | `204 No Content` |
| `POST` | `/orders/{order_id}/items` | Add an item to an order | `201 Created` |
| `GET` | `/orders/{order_id}/items` | List the items of an order | `200 OK` |
| `GET` | `/orders/{order_id}/items/{item_id}` | Read an item of an order | `200 OK` |
| `PUT` | `/orders/{order_id}/items/{item_id}` | Update an item of an order | `200 OK` |
| `DELETE` | `/orders/{order_id}/items/{item_id}` | Delete an item from an order | `204 No Content` |

Request bodies must be JSON with `Content-Type: application/json`.

### Root URL

```
GET /
```

```json
{
  "name": "Orders Service",
  "version": "1.0",
  "list_url": "/orders"
}
```

### Create an order

```
POST /orders
```

| Input | Required | Description |
|-------|----------|-------------|
| `customer_id` | yes | Integer id of the customer |
| `items` | yes | Non-empty list of items, each with `product_id`, `quantity` and `price` |

The new order has the status `pending`, its `total_amount` is calculated from the items, and the response has a `Location` header with the URL of the new order.

```bash
curl -i -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -d '{"customer_id": 42, "items": [{"product_id": 1001, "quantity": 2, "price": "10.50"}, {"product_id": 1002, "quantity": 1, "price": "5.00"}]}'
```

```json
{
  "order_id": 1,
  "customer_id": 42,
  "order_date": "2026-10-17T23:23:20.332362",
  "status": "pending",
  "total_amount": "26.00",
  "items": [
    {"id": 1, "order_id": 1, "product_id": 1001, "quantity": 2, "price": "10.50"},
    {"id": 2, "order_id": 1, "product_id": 1002, "quantity": 1, "price": "5.00"}
  ]
}
```

Returns `400 Bad Request` if `customer_id` or `items` is missing, if `items` is empty, or if an item is invalid.

### List orders

```
GET /orders
GET /orders?customer_id=42
```

Returns a JSON list of orders, or an empty list if there are none. The optional `customer_id` query parameter keeps only the orders of that customer and must be an integer, otherwise the service returns `400 Bad Request`.

### Read, update and delete an order

```
GET    /orders/{order_id}
PUT    /orders/{order_id}
DELETE /orders/{order_id}
```

`PUT` takes a body with a positive integer `customer_id`:

```json
{"customer_id": 43}
```

Items are not changed through this endpoint, so a body containing `items` is rejected with `400 Bad Request`. Use the items endpoints below instead.

All three return `404 Not Found` if the order does not exist.

### Add an item to an order

```
POST /orders/{order_id}/items
```

| Input | Required | Description |
|-------|----------|-------------|
| `product_id` | yes | Positive integer |
| `quantity` | yes | Positive integer |
| `price` | yes | Number, zero or greater |

Returns `201 Created` with the new item and a `Location` header, and adds `price * quantity` to the order's `total_amount`. Returns `400 Bad Request` for an incomplete or invalid body and `404 Not Found` if the order does not exist.

### List, read, update and delete an item

```
GET    /orders/{order_id}/items
GET    /orders/{order_id}/items/{item_id}
PUT    /orders/{order_id}/items/{item_id}
DELETE /orders/{order_id}/items/{item_id}
```

- `GET .../items` returns the items of the order, or an empty list if it has none.
- `PUT` replaces the item. `product_id`, `quantity` and `price` are all required, an `order_id` in the body is ignored, and the order's `total_amount` is recalculated. It returns `200 OK` with the updated item, or `400 Bad Request` for an incomplete or invalid body.
- `DELETE` removes the item, keeps the order and recalculates its `total_amount`.
- All of them return `404 Not Found` if the order does not exist. The item endpoints also return `404 Not Found` if the item does not exist or belongs to a different order.

## Errors

Every error is returned as JSON, never as an HTML page:

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "404 Not Found: Order with id '0' was not found."
}
```

| Status | Error | When |
|--------|-------|------|
| `400` | Bad Request | The body is missing, not JSON, incomplete or invalid |
| `404` | Not Found | The order or item does not exist |
| `405` | Method not Allowed | The HTTP method is not supported by the URL |
| `500` | Internal Server Error | An unexpected error in the service |

## Getting Started

The project is built to run in a [Visual Studio Code Dev Container](https://code.visualstudio.com/docs/devcontainers/containers), which provides Python, the tools, and a PostgreSQL database.

1. Install [Docker](https://www.docker.com/), [Visual Studio Code](https://code.visualstudio.com/) and its **Dev Containers** extension
2. Clone this repository and open the folder in VS Code
3. Choose **Reopen in Container** when VS Code asks (or run **Dev Containers: Reopen in Container** from the command palette)

The container sets `DATABASE_URI` to its PostgreSQL service, so no other configuration is needed. The tables are created when the service starts, and `flask db-create` recreates them.

## Running the Service

Inside the dev container:

```bash
make run
```

This is the same as `honcho start`. The service listens on <http://localhost:8080>, so you can check it with:

```bash
curl http://localhost:8080/
```

## Running the Tests

Inside the dev container:

```bash
make test    # unit tests with a coverage report, fails below 95% coverage
make lint    # flake8 and pylint
```

The tests are in the `tests` folder and cover the happy paths and the sad paths of every endpoint.

```text
.devcontainer/             - VS Code Dev Container with PostgreSQL
Makefile                   - run, test and lint commands
Procfile                   - process definition for honcho and gunicorn
```
