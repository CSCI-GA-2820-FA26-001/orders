[![Python](https://img.shields.io/badge/Language-Python-blue.svg)](https://python.org/)
[![CI](https://github.com/CSCI-GA-2820-FA26-001/orders/actions/workflows/ci.yml/badge.svg)](https://github.com/CSCI-GA-2820-FA26-001/orders/actions/workflows/ci.yml)
[![Codecov](https://codecov.io/gh/CSCI-GA-2820-FA26-001/orders/branch/master/graph/badge.svg)](https://codecov.io/gh/CSCI-GA-2820-FA26-001/orders)

A RESTful microservice for the eCommerce back end built by the Orders squad of NYU CSCI-GA.2820 DevOps and Agile Methodologies (Fall 2026). An **Order** is a collection of **order items** created from products and quantities.

The service is written in Python with Flask, stores its data in PostgreSQL through SQLAlchemy, and returns JSON for every response, including errors. It is tested with GitHub Actions, packaged as a Docker image, and deployed to Kubernetes.

## Data Model

### Order

| Field | Type | Notes |
|-------|------|-------|
| `order_id` | integer | Generated by the service |
| `customer_id` | integer | The customer that placed the order, must be a positive integer |
| `order_date` | datetime (ISO 8601) | Defaults to the time the order is created |
| `status` | string | One of `pending`, `processing`, `shipped`, `delivered`, `cancelled`. Defaults to `pending` |
| `total_amount` | decimal string | Calculated by the service as the sum of `price * quantity` of all items, `0.00` for an order without items |
| `items` | list of order items | Nested in every order response, can be empty |

### Order Item

| Field | Type | Notes |
|-------|------|-------|
| `id` | integer | Generated by the service |
| `order_id` | integer | The order the item belongs to |
| `product_id` | integer | Must be a positive integer |
| `quantity` | integer | Must be a positive integer |
| `price` | decimal string | Unit price, must be zero or greater |

Deleting an order also deletes its items.

### Validation

Orders are validated in the model, not in the routes. `Order.deserialize()` checks the incoming data and fills in the Order and its items, and raises a `DataValidationError` for bad data, which the service returns as `400 Bad Request` with the reason in `message`. `POST /orders` uses it to create orders.

The model also has query methods used by the service: `Order.find_by_order_id()` and `Order.find_by_status()`.

## API Endpoints

| Method | URL | Description | Success |
|--------|-----|-------------|---------|
| `GET` | `/health` | Health check for Kubernetes | `200 OK` |
| `GET` | `/` | Service name, version and the list URL | `200 OK` |
| `POST` | `/orders` | Create an order, with or without items | `201 Created` |
| `GET` | `/orders` | List all orders (optional `?customer_id=` and `?status=`) | `200 OK` |
| `GET` | `/orders/{order_id}` | Read an order | `200 OK` |
| `PUT` | `/orders/{order_id}` | Update an order's `customer_id` | `200 OK` |
| `DELETE` | `/orders/{order_id}` | Delete an order and its items | `204 No Content` |
| `PUT` | `/orders/{order_id}/cancel` | Cancel a `pending` order | `200 OK` |
| `POST` | `/orders/{order_id}/items` | Add an item to an order | `201 Created` |
| `GET` | `/orders/{order_id}/items` | List the items of an order | `200 OK` |
| `GET` | `/orders/{order_id}/items/{item_id}` | Read an item of an order | `200 OK` |
| `PUT` | `/orders/{order_id}/items/{item_id}` | Update an item of an order | `200 OK` |
| `DELETE` | `/orders/{order_id}/items/{item_id}` | Delete an item from an order | `204 No Content` |

Request bodies must be JSON with `Content-Type: application/json`.

### Health check

```
GET /health
```

```json
{"status": "OK"}
```

Kubernetes can call this endpoint to check that the service is running.

### Root URL

```
GET /
```

```json
{
  "name": "Orders Service",
  "version": "1.0",
  "list_url": "/orders"
}
```

### Create an order

```
POST /orders
```

| Input | Required | Description |
|-------|----------|-------------|
| `customer_id` | yes | Positive integer id of the customer |
| `items` | no | List of items, each with `product_id`, `quantity` and `price`. Defaults to an empty list |
| `status` | no | One of the valid statuses. Defaults to `pending` |
| `order_date` | no | ISO 8601 date and time. Defaults to now |
| `total_amount` | no | Overrides the calculated total. Normally left out so the service calculates it from the items |

The response is the new order with a `Location` header that holds the full URL of the order, generated with Flask `url_for()`, for example `Location: http://localhost:8080/orders/1`.

```bash
curl -i -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -d '{"customer_id": 42, "items": [{"product_id": 1001, "quantity": 2, "price": "10.50"}, {"product_id": 1002, "quantity": 1, "price": "5.00"}]}'
```

```json
{
  "order_id": 1,
  "customer_id": 42,
  "order_date": "2026-10-17T23:23:20.332362",
  "status": "pending",
  "total_amount": "26.00",
  "items": [
    {"id": 1, "order_id": 1, "product_id": 1001, "quantity": 2, "price": "10.50"},
    {"id": 2, "order_id": 1, "product_id": 1002, "quantity": 1, "price": "5.00"}
  ]
}
```

An order can be created without items and filled later with `POST /orders/{order_id}/items`:

```bash
curl -i -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -d '{"customer_id": 42}'
```

```json
{
  "order_id": 2,
  "customer_id": 42,
  "order_date": "2026-10-17T23:25:02.118205",
  "status": "pending",
  "total_amount": "0.00",
  "items": []
}
```

Returns `400 Bad Request` if the body is missing, `customer_id` is missing or not a positive integer, `items` is not a list, an item is incomplete or invalid, or `status` is not a valid status.

### List and query orders

```
GET /orders
GET /orders?customer_id=42
GET /orders?status=pending
GET /orders?customer_id=42&status=pending
```

Without query parameters, the service returns every order. A `customer_id` is not required.

| Query parameter | Description |
|-----------------|-------------|
| `customer_id` | Keep only the orders of this customer. Must be an integer, otherwise the service returns `400 Bad Request` |
| `status` | Keep only the orders with this status |

The parameters can be combined, and an order must match all of them. The response is a JSON list of orders, or an empty list if no order matches.

### Read, update and delete an order

```
GET    /orders/{order_id}
PUT    /orders/{order_id}
DELETE /orders/{order_id}
```

`PUT` takes a body with a positive integer `customer_id`:

```json
{"customer_id": 43}
```

Only `customer_id` is updated. Items are not changed through this endpoint, so a body containing `items` is rejected with `400 Bad Request`. Use the items endpoints below instead. To cancel an order, use the cancel action.

`GET` and `PUT` return `404 Not Found` if the order does not exist.

`DELETE` is idempotent. It returns `204 No Content` with an empty body both when the order existed and was deleted, and when the order does not exist.

### Cancel an order

```
PUT /orders/{order_id}/cancel
```

Cancelling is an action on an order, not an update of its fields, so it has its own URL and takes no body. Only a `pending` order can be cancelled.

| Order | Response |
|-------|----------|
| `pending` | `200 OK` with the order, its `status` is now `cancelled` |
| `processing`, `shipped`, `delivered` or `cancelled` | `409 Conflict`, the order is not changed |
| Does not exist | `404 Not Found` |

```bash
curl -X PUT http://localhost:8080/orders/1/cancel
```

### Add an item to an order

```
POST /orders/{order_id}/items
```

| Input | Required | Description |
|-------|----------|-------------|
| `product_id` | yes | Positive integer |
| `quantity` | yes | Positive integer |
| `price` | yes | Number, zero or greater |

Returns `201 Created` with the new item and a `Location` header with the full URL of the item, and adds `price * quantity` to the order's `total_amount`. Returns `400 Bad Request` for an incomplete or invalid body and `404 Not Found` if the order does not exist.

### List, read, update and delete an item

```
GET    /orders/{order_id}/items
GET    /orders/{order_id}/items/{item_id}
PUT    /orders/{order_id}/items/{item_id}
DELETE /orders/{order_id}/items/{item_id}
```

- `GET .../items` returns the items of the order, or an empty list if it has none.
- `PUT` replaces the item. `product_id`, `quantity` and `price` are all required, an `order_id` in the body is ignored, and the order's `total_amount` is recalculated. It returns `200 OK` with the updated item, or `400 Bad Request` for an incomplete or invalid body.
- `DELETE` removes the item, keeps the order and recalculates its `total_amount`.
- All of them return `404 Not Found` if the order does not exist. The item endpoints also return `404 Not Found` if the item does not exist or belongs to a different order.

## Errors

Every error is returned as JSON, never as an HTML page:

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "404 Not Found: Order with id '0' was not found."
}
```

| Status | Error | When |
|--------|-------|------|
| `400` | Bad Request | The body is missing, not JSON, incomplete or invalid |
| `404` | Not Found | The order or item does not exist |
| `405` | Method not Allowed | The HTTP method is not supported by the URL |
| `409` | Conflict | The order cannot be cancelled in its current status |
| `415` | Unsupported media type | The request is not `application/json` |
| `500` | Internal Server Error | An unexpected error in the service |

## Getting Started

The project is built to run in a [Visual Studio Code Dev Container](https://code.visualstudio.com/docs/devcontainers/containers), which provides Python, Docker, K3D, `kubectl`, the other tools, and a PostgreSQL database.

1. Install [Docker](https://www.docker.com/), [Visual Studio Code](https://code.visualstudio.com/) and its **Dev Containers** extension
2. Clone this repository and open the folder in VS Code
3. Choose **Reopen in Container** when VS Code asks (or run **Dev Containers: Reopen in Container** from the command palette)

The container sets `DATABASE_URI` to its PostgreSQL service, so no other configuration is needed. The tables are created when the service starts, and `flask db-create` recreates them.

## Running the Service

Inside the dev container:

```bash
make run     # start the service with honcho and gunicorn
```

The service listens on <http://localhost:8080>, so you can check it with:

```bash
curl http://localhost:8080/health
```

## Running the Tests

Inside the dev container:

```bash
make test    # unit tests with a coverage report, fails below 95% coverage
make lint    # flake8 and pylint
```

The tests are in the `tests` folder and cover the happy paths and the sad paths of every endpoint. The minimum test coverage is **95%**. `make test` fails below it, and so does CI.

## Continuous Integration

Every push to `master` and every pull request against `master` runs the GitHub Actions workflow in [.github/workflows/ci.yml](.github/workflows/ci.yml). It:

1. Starts a PostgreSQL 15 service container for the tests
2. Installs Python 3.12 and the dependencies from the `Pipfile`
3. Lints the code with `flake8` and `pylint`
4. Runs the unit tests with `pytest`, failing below 95% coverage
5. Uploads the coverage report to [Codecov](https://codecov.io/gh/CSCI-GA-2820-FA26-001/orders), which uses the `CODECOV_TOKEN` repository secret

The CI and Codecov badges at the top of this file show the current results for `master`. A pull request should only be merged when CI passes.

## Docker Image

The [Dockerfile](Dockerfile) builds a production image from `python:3.12-slim`. It installs only the production dependencies from `Pipfile.lock`, copies `wsgi.py` and the `service` package, and runs `gunicorn` on port `8080` as a non-root user. `.dockerignore` keeps tests, Git data and local files out of the image.

```bash
make build   # build cluster-registry:5000/orders:1.0
make push    # push it to the K3D cluster registry
```

The registry, name and tag can be changed with `REGISTRY`, `IMAGE_NAME` and `IMAGE_TAG`, for example `make push REGISTRY=localhost:5000`.

The image does not contain database settings. The database is set at run time with the `DATABASE_URI` environment variable:

```bash
docker run -p 8080:8080 \
  -e DATABASE_URI=postgresql+psycopg://postgres:postgres@<db-host>:5432/postgres \
  cluster-registry:5000/orders:1.0
```

## Kubernetes Deployment

The service runs on a local [K3D](https://k3d.io/) Kubernetes cluster. The manifests are in the `k8s` folder:

| File | Resource | Purpose |
|------|----------|---------|
| `k8s/deployment.yaml` | Deployment `orders` | Runs the `cluster-registry:5000/orders:1.0` image on port `8080` and sets `DATABASE_URI` to the PostgreSQL service |
| `k8s/service.yaml` | Service `orders` | `ClusterIP` service that sends port `8080` to the Orders pods |
| `k8s/ingress.yaml` | Ingress `orders` | Routes every path (`/`) from the cluster load balancer to the `orders` service |
| `k8s/postgres/statefulset.yaml` | StatefulSet `postgres` | Runs PostgreSQL 16 with the `orders` database and a 1Gi persistent volume |
| `k8s/postgres/service.yaml` | Service `postgres` | Headless service that gives the database the stable host name `postgres` on port `5432` |

### PostgreSQL in Kubernetes

PostgreSQL runs as a StatefulSet instead of a Deployment because a database needs a stable identity and its own storage. The `volumeClaimTemplates` section creates a `PersistentVolumeClaim` named `postgres-data` that is mounted at `/var/lib/postgresql/data`, so the data survives when the pod restarts.

The headless `postgres` service makes the database reachable inside the cluster at `postgres:5432`. The Orders Deployment connects to it with:

```text
DATABASE_URI=postgresql+psycopg://postgres:postgres@postgres:5432/orders
```

The Orders service creates its tables on start up.

### Deploying to K3D

1. Create the cluster with a registry and a load balancer on port `8080`:

   ```bash
   make cluster
   ```

2. So that Docker on your machine can reach the cluster registry, add this line to `/etc/hosts` once:

   ```text
   127.0.0.1    cluster-registry
   ```

3. Build the image and push it to the cluster registry:

   ```bash
   make build
   make push
   ```

4. Deploy PostgreSQL and the Orders service (this runs `kubectl apply -R -f k8s/`):

   ```bash
   make deploy
   ```

5. Check that the pods are running and the resources exist:

   ```bash
   kubectl get pods
   kubectl get services
   kubectl get ingress
   kubectl get pvc
   ```

   Wait until the `orders` and `postgres-0` pods are `Running`. `kubectl logs deploy/orders` shows the service logs.

6. Use the Orders API through the Ingress:

   ```bash
   curl http://localhost:8080/health
   curl http://localhost:8080/orders
   ```

To delete the cluster, run `make cluster-rm`.

## Project Structure

```text
service/                   - service python package
├── __init__.py            - application factory, database and logging setup
├── config.py              - configuration parameters
├── routes.py              - REST API endpoints
├── models/                - database models
│   ├── __init__.py
│   ├── persistent_base.py - shared create, update, delete and find methods
│   ├── order.py           - Order model, validation, deserialize() and queries
│   └── order_item.py      - OrderItem model
└── common                 - common code package
    ├── cli_commands.py    - Flask command to recreate all tables
    ├── error_handlers.py  - JSON error handling
    ├── log_handlers.py    - logging setup code
    └── status.py          - HTTP status constants

tests/                     - test cases package
├── factories.py           - factory for testing with fake objects
├── test_cli_commands.py   - test suite for the CLI
├── test_models.py         - test suite for the models
└── test_routes.py         - test suite for the service routes

k8s/                       - Kubernetes manifests
├── deployment.yaml        - Orders Deployment
├── service.yaml           - Orders Service
├── ingress.yaml           - Ingress to the Orders Service
└── postgres/
    ├── statefulset.yaml   - PostgreSQL StatefulSet with persistent storage
    └── service.yaml       - PostgreSQL headless Service

.github/
├── workflows/ci.yml       - GitHub Actions CI with Codecov
└── ISSUE_TEMPLATE/        - templates for user stories and bug reports

.devcontainer/             - VS Code Dev Container with PostgreSQL
config/                    - K3D cluster registry configuration
Dockerfile                 - production image for the service
.dockerignore              - files left out of the image
Makefile                   - run, test, lint, build, push and Kubernetes commands

wsgi.py                    - WSGI entry point for gunicorn
```
